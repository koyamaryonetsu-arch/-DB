## 1. はかる どうぐ（`tools/load-measure.mjs`）
```
node tools/load-measure.mjs --net 4g,slow4g --runs 2 [--cpu 4] [--http] [--nopack] [--out 結果.json]
node tools/load-measure.mjs --analyze   # main.js から import を たどって 大きさを しらべる（ブラウザ なし）
```
- この フォルダの `public/`・`server/` を 一時フォルダに コピーし、家族サーバーを 立てる（自動更新は 切る・`version.json` は にせの sha）
- Funnel の まね: **https ＋ HTTP/2** の 入り口（その 場で 作った 証明書。chromium には 公開かぎの ハッシュで「正しい」と 教える。まちがいの 証明書だと キャッシュが 効かない ため）
- 回線の しぼり: **TCP の 中みを 遅らせる 入り口**（下りの 速さ・おうふくの 時間。つなぎ全部で 1本の 線を わけあう）
  - 4G: 下り 9Mbps・上り 4Mbps・おうふく 170ms／おそい 4G: 下り 1.6Mbps・上り 0.75Mbps・300ms
  - CDP の しぼり（`Network.emulateNetworkConditions`）は ページの 通信だけで、Service Worker の 通信に かからない。前と 後を 同じ 条件で くらべる ため、回線 そのものを まねた
- 3つの 場面（1つの ブラウザの 中で つづけて）: はじめて（キャッシュ 空）→ 2回目（ページを 閉じて 開きなおす。Service Worker も 止めて おく＝スマホで しばらく して 開いた まね）→ 更新の あと（サーバーを 止め、5ファイルの 中みと `version.json` の sha を かえて 立てなおす）
- はかる もの: 通信の 回数（サーバーに とどいた 数）・送られた バイト（回線の 上の 下り。TLS も ふくむ）・タイトル画面（`.title-screen`）が 出る までの 時間・JS を 動かした 時間（CDP の `ScriptDuration`）・字の ファイルの 数と バイト
- `--runs 2`: 2回 はかり、時間は 速い ほうを とる（この PC は ほかの 仕事も して いて、時間が ぶれる）

## 2. しくみ
### 2-1. 家族サーバーの 送り方（`server/static.js`・`server/stamp.js`）
- 文字の ファイル（js・css・html・json・svg・txt・webmanifest・ttf）を **brotli（品質5）か gzip** で 送る。ちぢめた 結果は メモリに とって おき、ファイルが かわったら（大きさ・時こくで 見る）作りなおす。`Vary: Accept-Encoding`。字（woff2）・画像は ちぢめない
- 起動の あと 少しずつ（1ファイルずつ `setImmediate`）ちぢめて おく。パックは べつの 糸（zlib の 非同期）で ちぢめる（ゲームの 動きを 止めない）
- **ETag と 304**（文字の ファイルは 中みの ハッシュ、字・画像は 大きさと 時こく）
- **版つきの 読みこみ**: 送る 時に JS の `import`（`from`・`import()`・`import '…'`）と `index.html` の 読みこみ（main.js・style.css・fonts.css）に `?v=<版>` を つける（`build-site.mjs` と 同じ 関数。ファイルは かえない）
  - `?v=` が 今の 版 → `Cache-Control: public, max-age=31536000, immutable`（2回目からは モジュールの 通信が 0回）
  - `?v=` が ちがう 版（更新の 直後に 古い ページが 動いて いる）→ 今の 中みを 返すが `no-cache`（まちがった 中みを 1年 とって おかせない）
  - `?v=` なし・`index.html` → 今まで どおり `no-cache`（ETag で 304）。字の ファイルは 30日（今まで どおり）
- **版**: `version.json` の sha（先の 12文字）。ない 時（開発中）や 起動の あとに ファイルが かわった 時は、`public/` の ファイルの ようす（パス・大きさ・時こく）の ハッシュから 作る（`index.html` を 送る たびに しらべなおす。ほかは 2秒に 1回まで）。ファイルが かわれば 版も かわるので、古い 中みが 出つづけない
- client の 中を しらべた: `import()` は 8か所 とも モジュールからの 相対パス（`?v=` が つく）。文書からの 相対パスで JS を 読む 所・`fetch('js/…')`・Worker は ない（テストで 見はる）

### 2-2. パック ＋ Service Worker（https と この PC だけ）
- サーバー: `pack-manifest.json?v=<版>`（`{ v, size, files: { パス: 中みの ハッシュ } }`）と `pack.json?v=<版>`（`{ v, files: { パス: [ハッシュ, 中み] } }`。中みは `?v=` を つける 前）。全部の JS・CSS（sw.js 以外）。パックは br（品質9）で 約3.5MB（gzip が 先に できるので、br が まだ なら gzip で 送る）
- ひとりで遊ぶサイト: `build-site.mjs` が 同じ 2つの ファイルを 書く。サイトの index.html は `sw.js?nav=off` を 登録する（サイトでは「家族サーバーに つながりません」の 案内を 出さない）
- 起動（`server/boot-loader.js` を `stampHtml` が index.html に うめこむ）:
  1. Service Worker が ページを 見て いれば「版 v を 用意して」と たのむ（`kz-prepare`）。はじめての 訪問は その 場で 登録し、動きだすのを 4びょう まで まつ
  2. SW は 目録を 読み、**持って いない ハッシュだけ** 取りに 行く（足りないのが 40ファイル 以下なら 1つずつ 並行で・多ければ パック 1本）。ハッシュを たしかめて メモリへ
  3. 「できた」の 返事 → ページが `js/main.js?v=<版>` を 読みはじめる。SW は 版つきの JS・CSS を メモリ（なければ Cache Storage）から `?v=` を つけて 返す
  4. 返事の あと: その 版の 中み 全部を **1つに まとめて** Cache Storage に しまい（1つずつ しまうと 2回目に 読むのが おそい）、目録を 書く（全部 しまえた しるし）。のこすのは 今の 版と 直前の 版だけ
- 読みこみ中は 画面の 下に「読みこみ中（42%）」（パックを 取って いる あいだ）。main.js が タイトルを 出したら 消す
- 2回目: SW は しまった まとめを 1回 読む だけ（通信は index.html・api/info・WebSocket だけ）
- 更新の あと: 目録 1本 ＋ かわった ファイルだけ（前の 版の まとめと くらべる）

## 4. 安全の しくみ（家族が 遊べなく なるのが 最悪）
- SW は **加速だけ**。次の 時は すぐ 今まで どおり ふつうに 読む:
  - Service Worker が ない・http（家の Wi-Fi）・`caches`／`MessageChannel` が ない
  - はじめての 訪問で SW が 4びょう 以内に 動かない・強い 読みこみ直しで SW が ページを 見て いない
  - 「たのんだ」のに 1.5びょう 返事（ack）が ない（この しくみの ない 古い SW。この 版を 入れた 直後の 1回だけ）
  - とちゅうで 8びょう 何も 来ない（回線が 止まった）・SW が しっぱいを 返した
- SW の 中でも、目録の 版が ちがう・ハッシュが 合わない・まとめが ない → その ファイルは ふつうに ネットから
- **`index.html` と ナビゲーションは 決して しまわない**（今の「古い ページが 出る ことは ない」は そのまま）。版は いつも ネットから 来た index.html で きまる
- 「家族サーバーが 止まって いる 時の 案内」（ナビゲーションの やり直しと 案内の ページ）は そのまま（`test/downpage.test.js`）
- 版つき（`?v=`）でない 読みこみ・ほかの オリジン・`api/`・`sw.js` には さわらない
- しまう 場所が たりない（古い iPhone の Cache Storage の 上限 など）→ その 回は メモリから 返し、7日の あいだは パックを 使わない（ふつうの 読みこみ＋ブラウザの キャッシュ）
- SW の 中で 使う API は iOS の Safari でも 動く もの（`caches`・`crypto.subtle.digest`・`ReadableStream` の `getReader`・`TextDecoder`・`MessageChannel`・`ExtendableMessageEvent.waitUntil`）。Chrome だけの もの（`navigationPreload`・static routing など）は 使って いない
- SW を かえても（`sw.js` は `no-cache`）、ブラウザが ページを 開く たびに 新しい sw.js を たしかめる（今まで どおり `skipWaiting`・`clients.claim`）

## 5. 止め方
- その 時だけ: アドレスに `?nopack`（例 `https://…ts.net/?nopack`）
- ずっと: ブラウザの 開発者ツールなどで `localStorage.kizuna_nopack = '1'`（もどす 時は 消す）
- 止めた 時も 2だんめ（圧縮・`?v=` の 1年 キャッシュ）は 効く
- サーバー がわで 止めたい 時: `server/static.js` の `stampHtml(…, { pack: true })` を `false` に する（index.html が SW に たのまなく なる）

## 6. 気を つける こと
- 家族の スマホには Tailscale アプリは ない。外出先は Funnel の https を ブラウザで 開く だけ（SW が 動く）。家の Wi-Fi の http では SW は 動かないので 2だんめ だけ
- はじめての 訪問は SW の 登録（約1びょう）を まって から パックを 取る。この 版を 入れた 直後の 1回は、古い SW が 返事を しないので 1.5びょう まって ふつうに 読む
- パックを 使った ページでは、モジュールは SW が 作った 返事なので、ブラウザの JS の コードキャッシュ（V8）が 効かない ことが ある。いまの 数字では JS の 時間に 大きな ちがいは 見えない
- 家族サーバーの 起動の あと、ファイルを ちぢめ おわる までの 数びょう（PC に よる）は、その 場で ちぢめる（少し おそい）。パックの br は できる まで gzip で 送る（約1MB 大きい）
- メモリ: 家族サーバーは 送る 中み（?v= つき）・ちぢめた 結果・パックで 約40MB ふえる。SW は 読みこみの あいだ 中みを メモリに おき、1分 使わなければ すてる。Cache Storage は 1つの 版で 約18MB（今の 版と 直前の 版）
- ひとりで遊ぶサイトでも `api/info` の 404 が コンソールに 1つ 出る（家族サーバーが あるかを 見る ため。前から ある）
- 測った 回線は まね。Funnel の 本当の 速さ・スマホの CPU では かわる（とくに JS の 時間。5 を 見る）

## 7. 4だんめ: はかっただけ・すすめ
### 7-1. はかった こと
- スマホの CPU の まね（`--cpu 4`。回線は しぼらない。3だんめ）:

| | タイトルまで | JS（ScriptDuration） | メインの 糸の 仕事（TaskDuration） |
|---|---:|---:|---:|
| CPU 1倍・はじめて／2回目／更新の あと | 6.5／5.5／4.7びょう | 1.4／1.3／1.2びょう | 2.8／2.8／2.5びょう |
| CPU 4倍・はじめて／2回目／更新の あと | 11.5／8.2／10.8びょう | 3.1／3.1／3.1びょう | 7.3／6.4／6.0びょう |
| CPU 4倍・`?nopack`（2だんめ だけ） | 13.9／8.7／15.0びょう | 4.0／2.7／4.2びょう | 7.3／5.5／9.0びょう |

  → 通信を なくしても、スマホ相当の CPU では **タイトルまで 8びょう ぐらい** かかる。いまの いちばんの 待ちは「JS を 読んで 動かす」（約880本の モジュールを 組み立てて 動かす）に うつった
- 字の ファイル: タイトルまでに 読むのは woff2 16本・**136KB** だけ（全部で 484本・7.5MB だが、使う 字の 分だけ 読まれる）。30日 とっておける。`fonts.css`（364KB）は 2だんめで `?v=` つき（1年）に した → **手を 入れる ねうちは ない**
- タイトルまでに 読む JS（`--analyze`。main.js から import を たどった）: **874本・15.5MB**（ちぢめる 前）

| どこ | 本 | 大きさ |
|---|---:|---:|
| えがく（client/render） | 276 | 6.5MB（うち 戦いの えんしゅつ axfx 2.6MB・battlefx 0.96MB・主人公の え 0.76MB） |
| データ（shared/data） | 317 | 4.9MB |
| マップ（shared/maps） | 92 | 1.2MB |
| client（そのほか）・画面・せかいの 動き・そのほか | 189 | 2.9MB |
| うち 章ごとの データ（ch2〜ch8 の 名前の もの） | 95 | 1.78MB（11%） |

### 7-2. 見こみ と すすめ
- **章ごとの データを あとから 読む**: タイトルまでの JS の 11%（1.78MB・ちぢめて 約0.5MB）。はじめての 通信は おそい4G で 約2.5びょう へるが、2回目からは もう キャッシュで 0。JS の 時間は 大きさの わりあいで 見て 約0.3びょう（CPU 4倍）。データは サーバーの せかい（`shared/world`）も 使うので、なおす 所が 多い → **今は すすめない**（ねうちが 小さい）
- **戦いの えんしゅつを 戦いの 時に 読む**（axfx・battlefx 3.6MB・23%）: 大きさの わりあいで 見て、毎回の JS の 時間が CPU 4倍で 約0.7びょう、はじめての 通信が 約1MB（ちぢめて）へる 見こみ。さいしょの 戦いの 前（フィールドに 出た あと）に うらで 読みはじめれば 戦いは またない。`battle.js`・`render/` の 係と いっしょに やる ねうちは ある（**つぎに やるなら これ**）
- **まず しらべる**: CPU 4倍で メインの 糸の 仕事が 6〜7びょう（JS の 時間 3びょう ＋ モジュールの 組み立て・画面）。どの モジュールが import の 時に 重い 計算を して いるか（データの 表を 作る など）を CDP の Profiler で しらべると、ファイルを 分けるより 安く 速く できる かもしれない
- 字の ファイル: なにも しない（上の とおり）
- ビルド（1本に まとめる）は「ビルドなし・依存 0」の きまりが あるので しない。パック（3だんめ）で 通信は もう 1本に なって いる
