# 第78回: 引っこしコードを 根本から 直す（KIZUNA-5）

設計メモ `docs/plan-design-r77.md` の 3-1。魔物・技・たおした 数が ふえるたびに LINE の 上限（`LINE_MAX = 10000` 文字）に
ぶつかって、3回 その場しのぎで 直した（KIZUNA-3・4 の「やせさせる」書き方・たおした 数の ランレングス）。
今回は 本物の 圧縮・自動で 分ける・ファイルで 出し入れ の 3つで 直す。

## 1. わかった こと（はかって みたら）

- **今の ふつうの セーブでも、もう LINE の 1通に 入って いなかった**（KIZUNA-4 で 22900文字）。
  いちばん 大きいのは **きりの マップ（`c.explored`）**: 行った マップ ごとに base64 の ビットの 表（overworld だけで 3600文字）。
  前の テストの「いっぱい」の キャラには きりの マップが 入って いなかったので 気づかなかった
- 情報の 量（とくに 技を 使った 回数・たおした 数・図鑑・きりの マップ）が 多いので、どんな 圧縮でも
  「いちばん 大きな セーブを LINE_MAX の 60% 以下」は できない（下の 表。zlib -9 でも 5万文字）。
  なので「ふつうの セーブは 1通に よゆうを もって」「いちばん 大きな セーブは 自動で 3通に 分ける」を 目標に した

## 2. えらんだ 圧縮と 理由

候補（ちぢめる 前は KIZUNA-4 の「やせた」形 ＋ きりの マップの 書きかえ〈下の 3〉の JSON。数は base64url に した 文字数）:

| セーブ | もとの JSON | 前の コード | LZW（今までの） | deflate（zlib -9） | brotli（参考） | 文脈まぜ | **文脈まぜ＋下じき（KIZUNA-5）** | 書く／読む 時間（node） |
|---|---|---|---|---|---|---|---|---|
| 前のテストの「いっぱい」（仲間40・たおした数99・記録） | 35665 | 9791（KIZUNA-4） | 9737 | 6431 | 5475 | 5007 | **1717（1通・17%）** | 0.4秒／0.2秒 |
| ふつう（第4章くらい・仲間14・マップ90） | 56654 | 22907（KIZUNA-4） | 17604 | 12522 | 10815 | 9688 | **6334（1通・63%）** | 0.5秒／0.2秒 |
| いちばん大きい（下の 6） | 217132 | 85084（KIZUNA-4） | 73029 | 51307 | 42308 | 36870 | **25692（3通）** | 1.4秒／0.7秒 |

- **LZW**（今までの `pack`）… いちばん 弱い
- **deflate（LZ77＋ハフマン）** … node の `zlib -9` を 物さしに した。自分で 書いても zlib -9 より 縮む ことは ないので、
  この 数が deflate の 上限。文脈まぜより 3〜4わり 長い ので 作らなかった
- **brotli** … ブラウザで 同期で 使えない（参考）
- **文脈まぜ（context mixing）＋ 算術符号** ← えらんだ（`shared/world/transfer-pack.js`）
  - 1ビットずつ「つぎは 0 か 1 か」を、前の 1・2・3・4・6文字・1つ前の 文字・同じ ならびの くりかえし（match）から 予想し、
    重みを 学ぶ まぜ器（mixer）で まぜて、2つの 仕上げ（APM）を かけて、32ビットの 算術符号で 書く（lpaq と 同じ 考え）
  - **下じき（prime）**: ちぢめる 前と もどす 前に、セーブに よく 出る 名前（職業・技・道具・マップ・宝箱・フラグ・魔物の ID）と
    セーブの 形を 7万文字 読ませておく（zlib の 辞書と 同じ 考え）。ふつうの セーブで さらに 35% みじかく なる。
    `shared/world/transfer-prime.js` に 文字の まま 入れて **固定**（CRC を テストで 見はる）。魔物や 技が ふえても
    かえなくて よい（下じきに ない 名前も ちぢむ。少し 長く なる だけ）。かえたく なったら KIZUNA-6 に する
  - 依存なし・同期・純粋な JS。**整数の 計算だけ**（Math.exp などは 使わない。squash は lpaq の 33この 表から 整数で 作る）
    ので、node でも ブラウザでも まったく 同じ 結果（テストに 決まった 答えを 1つ 入れて、ブラウザでも たしかめた）
  - 下じきを 読ませた あとの 表は 1回だけ 作って とっておき、毎回 うつして 使う（1回め だけ 0.4〜1秒 よけいに かかる）
  - メモリ: 表は 1つ 13MB くらい（とっておく 分と 使う 分で 2つ）

## 3. きりの マップ（`c.explored`）の 書きかえ

きりは「歩いた 所の まわり（半径 R の まる。フィールド 8・ダンジョン 5。`client/field.js` の `reveal`）」を 晴らした もの。
なので **まるの まん中の ならび** だけ 書けば、読む ときに まるを ぬって ぴったり もどる（`packExplored` / `unpackExplored`）。

- まん中の こうほ ＝ まるが ぜんぶ 晴れて いる 所。いらない まん中（ほかの まるで ぜんぶ ぬれる 物）は へらす
- 書く 形: `{ e: "w.h.R:" ＋ まん中の 番号の さ（36進。. で つなぐ） }`。w・h・R も 書くので、読む ほうの マップの データに たよらない
- 書いた あとで もどして くらべ、**ぴったり 同じに ならない マップは 前の 形（base64）の まま**（マップの 大きさが かわった など）
- ふつうの セーブで きりの マップは 27000文字 → 1300文字くらい

## 4. コードの 形

```
KIZUNA-5-<CRC-32 8もじ>-<データの 文字数 36進>-<データ>
```

- データ = base64url（`A-Z a-z 0-9 - _` だけ。LINE・メール・メモ帳で こわれない）で 書いた [もとの バイト数（7ビットずつ）][算術符号の バイト]
- ちぢめる 前 = `{ v: SAVE_VERSION, at, char: slimChar5(char) }` の JSON（UTF-8）
  - `slimChar5` = KIZUNA-4 の `slimChar4` ＋ きりの マップ（上の 3）＋ 行った 所（`visited`）を 名前の ならびに
- CRC-32 は もとの JSON の バイトの もの。もどした あとで くらべる（1文字 ちがう・まざった → 「コードがこわれているみたい」）
- データの 文字数が あるので、**とちゅうで 切れた 時は「コードがとちゅうで切れています。最後まで全部コピーしてね」**。
  うしろに 文が ついて いても 読める
- 読む ときは 空白・改行・見えない 空白（U+200B〜D・FEFF）を とりのぞき、`KIZUNA-` より 前の 文（「ユイの引っこしコード」など）も すてる
- 出すのは KIZUNA-5 だけ。**KIZUNA-1〜4 も ずっと 読める**（前の 書き出しは `exportCodeV4` と して のこし、テストで 守る）

## 5. 分ける 時の 決まり（`splitCode` / `joinParts`）

LINE の 1通（`LINE_MAX`）に 入らない ときだけ 分ける。ふだんは 1通。

```
KIZUNA-5-P<何通め>/<ぜんぶで>-<まとめの しるし 8もじ>-<きれはしの 文字数 36進>-<きれはし>
```

- まとめの しるし = 分ける 前の コード ぜんたいの CRC-32。ちがう コードの きれはしが まざると「ちがう引っこしコードがまざっています」
- 同じ 長さに 分ける（1通 ＝ LINE_MAX − 30 文字まで）。`/` は データに 出ない 文字なので、きれはしの 区切りを まちがえない
- 読む 側は **どの じゅんで はっても よい**。1回に 何通 はっても よい・同じ ものを 2回 はっても よい。
  たりない ときは「3つに分かれたコードの、1・3つめを読みました。あと1つです」（`parseCode` は `partial: true`・`have`・`total`）
- きれはしの 文字数が あるので、きれはしの うしろに 文（「2通めです」など）が ついても・とちゅうで 切れても 分かる
  （「2つめのコードが、とちゅうで切れています」）
- そろったら つなげて、まとめの しるしを くらべてから ふつうの KIZUNA-5 と して 読む

## 6. 画面（`client/ui/title.js` の 引っこしコード）

- **書き出す**: 1通の ときは 今までどおり（コピー）。分ける ときは「コードが長いので、3つに分けました」と 出して、
  1つずつ わくと「1つめをコピー」。「全部まとめてコピー」（メモ・メール・AirDrop 用）も
- **ファイルで出す**: `kizuna-<キャラのID>-<日づけ>.txt`（名前は 英数字だけ。日本語だと「download」に なる ブラウザが ある）。
  スマホで 共有の メニュー（`navigator.share` で ファイル）が 使える ときは それで、だめなら ダウンロード。
  中みは 1行の 説明 ＋ まとめた コード（分けない。ファイルには 上限が ない）
- **連れてくる**: 分けた コードは 1つずつ はって「連れてくる」→「読んだコード: 1・3つめ（3つのうち）」と「あと1つです」。
  そろったら サーバー（ひとりモードは ブラウザの 中の 世界）へ 送る。「やりなおす」で ためた 分を すてる
- **ファイルから読む**: .txt を えらぶと、中の コードで そのまま 連れてくる（2MB より 大きい ファイル・コードが ない ファイルは ことわる）
- 1タップで 連れていく リンク（`#kizuna=`）は 今までどおり まとめた コード

## 7. これからの 見はり（`test/transfer-r78.test.js`）

- `test/transfer-big-save.js` が **データから 自動で**「いちばん 大きな セーブ」と「ふつうの セーブ」を 作る
  - いちばん 大きい: Lv150・全部の 職業を きわめて 覚えた 技 全部と ひらめき 全部を 使った（回数は 1〜9999）・お気に入り 60・
    使う 道具と 素材 全部 ＋ そうび 400・だいじな物 全部・預かり所 60・全部の フラグ・宝箱・きらきら・全部の マップ（きりは 60〜95% 晴れ）・
    全部の 魔物の たおした 数（1〜9999）と 図鑑（属性・落とした 物）・仲間 40（人 5）・あずかり所 60・幻の職業の 記録
  - 数は「小さい 物が 多く、大きい 物は 少し」（対数で 平ら）。きりは 歩いた 道すじから 作る
- 見はり: **ふつうの セーブは LINE_MAX の 70% 以下（1通）**・**いちばん 大きな セーブは 3通まで（3通の 90% 以下）**・
  どちらも zlib -9 より みじかい。魔物や 技・マップを 足して ここが 赤く なったら、上限に ぶつかる 前に 分かる
- ほかに: 決まった 答え（しくみや 下じきを かえると 前の コードが 読めなく なる ので 見はる）・どんな バイトでも もどる・
  切れた／1文字 ちがう コード・分けた コードの じゅんばん・たりない・まざった・前の KIZUNA-1〜4

## 8. 気を つける こと

- **`transfer-pack.js` の 予想の しくみ・`transfer-prime.js` は かえない**（かえると 前の KIZUNA-5 が 読めない）。
  かえる ときは KIZUNA-6 を 作って、KIZUNA-5 の 読みこみは のこす
- 新しい 版の サイトで 作った KIZUNA-5 は、古い 版（KIZUNA-4 まで しか 知らない）では 読めない（「引っこしコードではないみたい」）。
  家族サーバーと ひとりで遊ぶサイトの 版を そろえて おく
- 書く・読む 時間は node で 0.2〜1.5秒、さいしょの 1回は 下じきの ぶん 0.4〜1秒 よけいに かかる（スマホは その 数倍）
