# 新規案件 → 初期対応診断 → LINE通知（自動）

「🎬 TOHO 修理案件管理」データベースに**新しく登録された案件**を検出し、各案件について
**初期対応診断（＝誰に・何を・どの順番で相談すればよいかのジャッジ）**を自動生成する。
生成結果を **LINE送信キュー（Notion ページ）** に積み、最後に **Claude in Chrome 用の投稿指示**を出力して終了する。

実際の LINE グループへの投稿は **Claude in Chrome** が担当する（このセッションは LINE に直接アクセスしない）。
両者の受け渡しは **Notion の送信キューページ**を共有バスとして行う。

## 対象データベース

- DB: `🎬 TOHO 修理案件管理`
- data source: `collection://578384f2-5bde-4c7d-b112-b0d962060a9e`
- 主なプロパティ: `案件名`(title) / `劇場` / `内容` / `TOHO本社担当` / `進捗` / `受付日`(date) / `見積` / `アラート`(formula)

## シネマPJ メンバーと役割（初期対応診断のルーティング表）

| 担当 | 役割・守備範囲 | こんな案件はまずこの人 |
|---|---|---|
| **金子さん** | TOHO 一次窓口・市川/横浜・事務調整 | TOHO 全般の受付窓口、見積・請求・顧客連絡、配管/計画書 |
| **細萱さん（修治）** | 技術判断・大型/緊急・空調熱源 | 空調・チラー・GHP・熱源・スプリンクラー・防災、緊急故障の技術ジャッジ |
| **山口くん** | 現場対応・見積作成 | 現地調査・訪問・見積作成、夜間/応急の現場手配 |

> ※メンバーの LINE アカウント・表示名は LINE グループ側で対応づける（このコマンドは「誰に相談」までを文章で示す）。

## 実行ルール（重要）

- **OK 確認は不要**。検出 → 診断 → キュー登録 → Chrome 指示出力まで一気に行う。
- LINE へ**直接は送らない**（このセッションに LINE 接続はない）。送信は Claude in Chrome の役割。
- 二重通知を防ぐため、通知済みの案件は **案件ページのコメント marker** で判定してスキップする。
- 診断は推測で埋めず、社内の実データ（同 DB の類似案件・Notion・Google ドライブ）で裏取りする。
- 日本語。LINE 向けは短く・箇条書き中心（スマホで一目で判断できる体裁）。

## ステップ0: 送信キューページの用意（冪等）

1. `notion-search` で `📤 LINE送信キュー（シネマPJ）` を検索する。
2. 見つからなければ `notion-create-pages` で作成する（parent は `page_id: 35fd405a-0cb4-8192-adab-f9f4301d50c0` = koyama Daily Dashboard）。
   - icon: `📤`、title: `📤 LINE送信キュー（シネマPJ）`
   - 本文の冒頭に次の説明を入れる:
     > このページは Claude Code（案件検出）と Claude in Chrome（LINE投稿）の受け渡し用です。`- [ ]` が未送信、`- [x]` が送信済み。Claude in Chrome は未送信項目を上から処理し、投稿後にチェックを付けてください。
3. 以降、見つかった/作成したページの ID を「キューページ」として使う。

## ステップ1: 新規案件の検出

「直近に登録され、まだ LINE 通知していない案件」を集める。

1. `notion-search` を `data_source_url: "collection://578384f2-5bde-4c7d-b112-b0d962060a9e"`、
   `filters.created_date_range.start_date` = **本日の7日前**、`query: "新規 案件 修理 対応"`、`page_size: 25` で実行し、
   直近7日に**作成**された案件ページを集める。`受付日` ではなく**ページ作成日(createdTime)**を新規判定の基準にする。
2. 各候補について `notion-get-comments` を呼び、本文に `🔔LINE通知済` を含むコメントが既にあれば**通知済み＝除外**。
3. 残ったものが「新規・未通知の案件」。0件ならステップ6のサマリーへ。

## ステップ2: 案件情報の整理と裏取り

各対象案件について `notion-fetch` で詳細（`案件名 / 劇場 / 内容 / TOHO本社担当 / 進捗 / 受付日 / 見積 / アラート` とページ本文）を取得する。

`内容` だけで「何を相談すべきか」を判断しきれない場合は、推測せず以下で補完する（並列可）:

1. **同DBの類似案件**: 同じ `劇場` または似た `内容`（空調/チラー/映写室/配管 等）の過去案件を `notion-search`（data_source_url 指定）で探し、対応の定石・前例を把握。
2. **Notion 全体**: `notion-search` で劇場名・設備名・顧客名を検索（シネマPJ ページ、定例議事録など）。
3. **Google ドライブ**: `search_files` → `read_file_content` で見積・報告書・図面など関連資料を確認。

## ステップ3: 初期対応診断の生成

各案件について、上の**ルーティング表**と裏取り結果をもとに、次の3点を必ず埋める:

1. **緊急度**: 🔴至急（故障停止・ガス漏れ・水漏れ・安全/防災・興行に影響） / 🟡通常 / ⚪情報共有 のいずれか。
   - `アラート` プロパティが「遅延」「要確認」を示す場合や、`内容` に故障・停止・漏れ・緊急の語があれば 🔴 寄りに。
2. **一次窓口（まず誰に相談）**: ルーティング表から1名を主担当として指名。必要なら副担当も。
   - 例: 空調・熱源・チラー → 細萱さん（技術）＋山口くん（現場） / 見積・請求 → 金子さん / 大型・価格 → 小山さん。
3. **次の一手（何を準備/確認）**: 具体アクションを1〜3個（例: 現地写真の共有、型式・系統の特定、見積要否、訪問日の仮押さえ、青木さんへの一次連絡）。

判断材料がどうしても無い要素は断定を避け（「現地状況の確認後に判断」等）、空欄やプレースホルダは残さない。

## ステップ4: LINE通知文の組み立て

案件1件につき、スマホで一目判断できる短い投稿文を作る。体裁:

```
🎬 新規案件【<緊急度アイコン> <緊急度>】
劇場：<劇場>
案件：<案件名>
内容：<内容を1〜2行に要約>
本社担当：<TOHO本社担当>／受付：<受付日>

🧭 初期対応診断
・まず相談：<主担当>（理由を一言）
・サポート：<副担当 or なし>
・次の一手：<アクション1> / <アクション2>

🔗 Notion：<案件ページURL>
```

至急（🔴）の場合は先頭に `@here 至急ジャッジ希望` を付ける。

## ステップ5: 送信キューへ登録（Claude in Chrome 受け渡し）

ステップ0のキューページを `notion-update-page` で更新し、各案件の投稿文を**未送信項目**として追記する:

- 各案件を `- [ ] <案件名>（<劇場>）` の**チェックボックス見出し**にし、その直下に**ステップ4の投稿文を引用ブロック（>）**で丸ごと貼る。
- 既存のキュー項目は消さず**末尾に追記**する。

## ステップ6: 通知済みマーク

キュー登録できた各案件ページに `notion-create-comment` で
`🔔LINE通知済 <YYYY-MM-DD HH:mm> / 初期対応診断をLINE送信キューに登録` というコメントを付ける（次回以降の二重通知防止）。

## ステップ7: サマリー ＋ Claude in Chrome への指示出力

**1件以上登録した場合**、最後に次を表示して終了する（確認待ちしない）:

```
✅ 新規案件 N件を検出し、初期対応診断を LINE送信キューに登録しました。

[1] <案件名>（<劇場>）／緊急度 <…>／まず相談：<主担当>
[2] ...

▼ Claude in Chrome への依頼（このままコピーして Chrome 側のClaudeに渡してください）
---
シネマPJ の LINE 投稿をお願いします。手順書は `.claude/playbooks/line-post-chrome.md` の通り。
Notion「📤 LINE送信キュー（シネマPJ）」<キューページURL> を開き、未送信(- [ ])の項目を上から順に
シネマPJの LINE グループへ投稿し、投稿できたらチェック(- [x])を付けてください。
---
```

**0件だった場合**:

```
✅ 新規案件チェック完了。直近7日に未通知の新規案件はありませんでした。
```
