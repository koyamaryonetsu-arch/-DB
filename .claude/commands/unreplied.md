# 未返信メール返信アシスタント（自動）

17時時点の未返信メールのうち、**小山さん本人宛**の顧客・取引先メールを抽出し、文脈を調べて返信案を**自動生成し、確認を待たずに Gmail 下書きとして保存**する。

## ユーザー情報

- 自分のメールアドレス（複数）:
  - `koyama.ryonetsu@gmail.com`
  - `koyama@ryonetsu.com`
- 社内メンバー（参考）: 金子 `r.kaneko0511@gmail.com`、若山 `s.wakayama1327@gmail.com` / `s.wakayama@ryonetsu.com`、山口 `hs.yamaguchi0404@gmail.com`、大和 `a.oowa@ryonetsu-ai.com`

## 実行ルール（重要）

- **OK 確認は不要**。返信案を生成したら、待たずにそのまま `create_draft` で Gmail 下書きに保存する。
- 下書き保存までで止める。**送信は絶対にしない**（Gmail で小山さんが最終確認して送信する前提）。
- 送信は常に **全員に返信（Reply All）**。自分のアドレスは宛先から除外。
- 日本語ビジネス丁寧体。
- 完了後はサマリーを表示して**そのまま終了**。確認待ちはしない（スマホ通知は不要）。

## ステップ1: 小山さんが To 宛のメールを検索

`search_threads` を以下のクエリで実行（pageSize: 50）:

```
in:inbox newer_than:2d (to:koyama.ryonetsu@gmail.com OR to:koyama@ryonetsu.com) -category:promotions -category:social -category:updates -category:forums -from:noreply -from:no-reply -from:donotreply -from:notification -from:notifications -from:mailer-daemon -from:bounces -from:mailmag -from:mailnews -from:newsletter
```

**重要な設計意図**:
- `is:important` は使わない。Gmail の「重要」マークは不安定で、顧客が To 宛で送っても重要扱いされず取りこぼす原因になるため、条件から外している。
- `to:` で**小山さんが To（宛先）に入っているメールだけ**を最初から対象にする（CC のみのメールは検索段階で除外＝小山さんの方針）。
- `newer_than:2d` でルーティン起動時刻が多少ずれても取りこぼさないようにする。

ヒット 0 件、または以降のフィルタで対象0件でも即終了せず、ステップ6のサマリー報告へ進む。

## ステップ2: スレッド詳細取得と対象判定

各スレッドについて `get_thread`（messageFormat: FULL_CONTENT）を呼ぶ。並列実行可。各スレッドで以下を判定し、**1つでも該当したら除外**:

1. **返信済み**: スレッド内の最新メッセージの labelIds に `SENT` が含まれる（=自分が最後に送信済み）
2. **CC のみ（重要）**: スレッド最新の受信メッセージで、小山さんのアドレスが `toRecipients` に**含まれず** `ccRecipients` のみに入っている → **返信案を作らない。除外する。**
   - 小山さんが `toRecipients` に直接入っている場合のみ対象とする
3. **自動送信**: 最新受信メッセージの送信者アドレスのローカル部/ドメインが以下を含む:
   - `noreply`, `no-reply`, `donotreply`, `do-not-reply`
   - `notification`, `notifications`, `alert`, `alerts`
   - `mailer-daemon`, `bounces`, `postmaster`
   - `newsletter`, `news@`, `info@`, `marketing@`, `promo@`
   - ドメイン: `mailchimp`, `sendgrid`, `hubspot`, `marketo`, `salesforce`
4. **メルマガ**: ヘッダに `List-Unsubscribe` がある
5. **件名**: `配信停止`, `unsubscribe`, `メルマガ`, `定期配信`, `自動配信`, `【お知らせ】`（自動配信パターン）
6. **社内のみ**: 送信者・宛先がすべて社内メンバー/自分のみで、社外の顧客・取引先が関与しない

残ったものが「小山さん宛・顧客取引先からの未返信メール」=自動返信対象。

**【必須】To 宛なら必ず下書きを作る**:
- 上記 1〜6 の除外（返信済み / CCのみ / 自動送信 / メルマガ / 件名パターン / 社内のみ）の**いずれにも当たらず**、小山さんが To に入っている顧客・取引先メールは、**1件残らず必ず create_draft で下書きを作る**。
- 「内容的に返信不要そう」「お礼だけだから」等の**主観的判断でスキップしてはならない**。除外条件 1〜6 に機械的に当たる場合のみ除外し、それ以外は例外なく下書きを作成する。
- 返信内容に迷う要素があっても、下書きを作らない理由にはしない。ステップ3の方針（文脈を調べて妥当な案を作る／断定を避けた言い回しでカバー）で必ず本文を用意する。

## ステップ3: 文脈調査と返信案生成

各対象について、スレッド内の **最新の受信メッセージ** の本文を読み、返信案を作成する。

**返信に必要な情報（日程・金額・仕様・経緯・社内方針など）が本文だけで足りない場合**、推測で埋めず、また小山さんに質問もせず、以下の順で**文脈を自分で調べて**埋める:

1. **同一スレッドの過去メッセージ** をすべて読み、経緯・既出の数値や条件を把握
2. **Gmail 内の関連スレッド**: 同じ取引先・物件名・案件名で `search_threads` を再検索し、関連メールから情報を補完
3. **Notion**: `notion-search` で取引先名・物件名・案件名を検索し、ヒットしたページを `notion-fetch` で読んで情報補完
4. **Google ドライブ**: `search_files` で関連資料（見積・報告書・議事録等）を検索し、`read_file_content` で内容確認

調べた情報をもとに、**最も妥当と判断できる返信案**を作成する。根拠が複数ソースから取れた場合はそれに従う。どうしても判断材料が見つからない要素は、断定を避けた言い回し（「追って正式にご連絡いたします」等）でカバーし、不自然に空欄やプレースホルダを残さない。

返信案の体裁:
- 書き出し: 「いつもお世話になっております。」など状況に応じて
- 本文: 受信内容への具体的応答（質問への回答、日程調整、依頼対応など）
- 結び: 「何卒よろしくお願いいたします。」など
- 署名は含めない（Gmail の署名機能に任せる）

## ステップ4: 下書き保存（全員に返信 / Reply All・OK不要）

各対象について、生成と同時に `create_draft` を呼ぶ。各スレッドの **最新の受信メッセージ** から宛先を組み立てる:

1. `to`: 最新受信メッセージの送信者アドレス（`sender`）
2. `cc`: 最新受信メッセージの `toRecipients` + `ccRecipients` を結合し、以下を除外:
   - 自分のアドレス（`koyama.ryonetsu@gmail.com`, `koyama@ryonetsu.com`、大文字小文字無視）
   - `to` と重複するもの
   - 重複（大文字小文字無視で一意化）
3. `subject`: 元の件名に `Re: ` が無ければ付与
4. `body`: ステップ3の返信案
5. `replyToMessageId`: 返信対象となる最新の受信メッセージのID

社内メンバーが CC に入っている場合もそのまま残す（全員に返信）。並列実行可。

## ステップ5: 参考調査の明示

返信案にステップ3でメール外（Notion / ドライブ / 別スレッド）の情報を使った場合、その件はサマリーで「※文脈補完: 〇〇（情報源）」と明示する。小山さんが Gmail で確認する際の判断材料にする。

## ステップ6: サマリー報告（表示して終了。確認待ちしない）

**1件以上保存した場合**:

```
✅ 本日 HH:MM 時点の未返信メールチェック完了。下書き N件を作成しました。

[1] <件名>
    To: <addr> / Cc: <addr...>
    ※文脈補完: <情報源>（使った場合のみ）
[2] ...

Gmail の下書きフォルダで内容を確認のうえ送信してください。
```

**0件だった場合**:

```
✅ 本日 HH:MM 時点の未返信メールチェック完了。

返信が必要な小山さん宛の顧客・取引先メールはありませんでした。

（参考）検索ヒット N件の内訳: 返信済み a件 / CCのみ・他メンバー担当 b件 / 自動メール・社内のみ c件
```

サマリーを表示したら**そのまま終了する**。`了解` 等の確認は求めない。
