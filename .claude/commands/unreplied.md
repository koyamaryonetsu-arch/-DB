# 未返信メール返信アシスタント

本日（17時時点）の未返信メールのうち、顧客・取引先からのものに絞って返信案を作成し、ユーザーの OK 確認後に Gmail の下書きとして保存する。

## ユーザー情報

- 自分のメールアドレス（複数）:
  - `koyama.ryonetsu@gmail.com`
  - `koyama@ryonetsu.com`
- 送信は常に **全員に返信（Reply All）** で行う。自分のアドレスは宛先から除外する。

## 実行ルール

- 独断で下書きを保存しない。必ずユーザーの「OK」を待つ。
- 下書き保存後の送信は行わない（Gmail でユーザーが最終確認して送信する前提）。
- 日本語ビジネス丁寧体で返信案を作成する。
- **返信に必要な情報が不足している場合は、勝手に推測で埋めない**。ユーザーに確認質問する。

## ステップ1: 重要メールを検索

`search_threads` を以下のクエリで実行（pageSize: 50）:

```
is:important in:inbox newer_than:1d -category:promotions -category:social -category:updates -category:forums -from:noreply -from:no-reply -from:donotreply -from:notification -from:notifications -from:mailer-daemon -from:bounces
```

ヒット 0 件なら「本日該当する未返信メールはありません」と報告して終了。

## ステップ2: スレッド詳細取得と未返信判定

各スレッドについて `get_thread`（messageFormat: FULL_CONTENT）を呼ぶ。並列実行可。

各スレッドで以下を判定:

1. **未返信判定**: スレッド内の **最新メッセージ** の labelIds に `SENT` が含まれていない（=自分が最後に送ったメッセージではない）
2. **自動送信除外**: 最新の受信メッセージの送信者アドレスのローカル部 / ドメインが以下を含む場合は除外:
   - `noreply`, `no-reply`, `donotreply`, `do-not-reply`
   - `notification`, `notifications`, `alert`, `alerts`
   - `mailer-daemon`, `bounces`, `postmaster`
   - `newsletter`, `news@`, `info@`, `marketing@`, `promo@`
   - ドメイン: `mailchimp`, `sendgrid`, `hubspot`, `marketo`, `salesforce` (一斉送信ESP)
3. **ヘッダ判定**: メッセージヘッダに `List-Unsubscribe` がある場合はメルマガと判定して除外
4. **件名判定**: 件名に以下を含む場合は除外: `配信停止`, `unsubscribe`, `メルマガ`, `定期配信`, `自動配信`, `【お知らせ】`(自動配信パターン)

残ったものが「顧客・取引先からの未返信メール」候補。

## ステップ3: 内容理解度の評価

各候補について、スレッド内の **最新の受信メッセージ** の本文を読み、返信に必要な情報がそろっているかを判定:

- **A. そのまま返信OK**: 報告・連絡・承知の返事で済むもの、お礼への返答、お待ちいただく旨の汎用回答で対応できるもの
- **B. 要確認**: 受信メールに具体的な質問・依頼・選択肢があり、回答するために小山さんからの情報（日程・金額・仕様・社内方針など）が必要なもの

判断に迷うものは B 扱いにし、推測で埋めない。

## ステップ4: 返信案生成

- **A のもの**: 返信案を作成
  - 書き出し: 「いつもお世話になっております。」など
  - 本文: 受信内容に対する具体的な応答
  - 結び: 「何卒よろしくお願いいたします。」など
  - 署名は含めない（Gmail の署名機能に任せる）
- **B のもの**: 返信案は作らず、`要確認事項` を箇条書きで明示

## ステップ5: ユーザーに提示

冒頭サマリー:

```
本日 HH:MM 時点の未返信メール: N件
  ├ そのまま返信OK: X件
  └ 要確認:         Y件
```

各件の表示フォーマット:

```
## [1] <件名>  ← [そのまま返信OK] または [要確認]
- From: <差出人名> <<アドレス>>
- 全員に返信した場合の宛先: To=<アドレス> / Cc=<アドレス1, アドレス2, ...>
- 受信: <YYYY-MM-DD HH:MM>
- 要点: <受信内容の3行以内の要約>

# A の場合
- 返信案:
  ---
  <返信案本文>
  ---

# B の場合
- 返信に必要な情報:
  - <小山さんに確認したい事項1>
  - <小山さんに確認したい事項2>
```

最後に以下を案内:

> ### アクション
> - 「そのまま返信OK」の X 件を保存: `OK`
> - 「要確認」に回答（番号指定で具体的内容）: `[2] 5/22の14時で、金額は79,000円で進めて`
> - 個別修正: `1: もう少し簡潔に`
> - スキップ: `skip`

ユーザーが要確認項目に回答したら、その内容を反映して返信案を生成し、再提示してから保存。

## ステップ6: 下書き保存（必ず全員に返信 / Reply All）

ユーザー承認後、選択された各案について `create_draft` を呼ぶ。

各スレッドの **最新の受信メッセージ** から宛先を組み立てる:

1. `to`: 受信メッセージの送信者アドレス（`sender`）
2. `cc`: 受信メッセージの `toRecipients` + `ccRecipients` を結合し、以下を除外:
   - 自分のアドレス: `koyama.ryonetsu@gmail.com`, `koyama@ryonetsu.com`（大文字小文字無視）
   - `to` に入れたアドレス
   - 重複（大文字小文字無視で一意化）
3. `subject`: 元の件名に `Re: ` が無ければ付与
4. `body`: ステップ4の返信案
5. `replyToMessageId`: スレッド内の **返信対象となる最新の受信メッセージのID**

「全員に返信」なので、社内メンバー（金子・若山・山口・大和など）が CC に入っている場合もそのまま残す。

並列実行可。

## ステップ7: サマリー報告

完了後、以下を表示:

- 保存した下書き件数と、各件の `To` / `Cc` / 件名
- 「要確認」だが情報未回答で **保留**となっている件があれば、その件名一覧
- 「Gmail の下書きフォルダで内容を確認のうえ送信してください」
