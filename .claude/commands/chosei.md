## 実行ルール（重要）

- **OK 確認は不要**。返信案を生成したら、待たずにそのまま `create_draft` で Gmail 下書きに保存する。
- 下書き保存までで止める。**送信は絶対にしない**。
- 送信は常に **全員に返信（Reply All）**。自分のアドレスは宛先から除外。
- 日本語ビジネス丁寧体。署名は含めない（Gmail の署名機能に任せる）。
- 完了後はサマリーを表示して**そのまま終了**。確認待ちはしない。
- カレンダーへの直接接続は無い。確定予定は Notion とメールから推定するため、**断定できない時間帯は「仮押さえ」「確定は追ってご連絡」等の表現にとどめ、勝手に確定文言を使わない**。

## ステップ1: 日程調整メールを検索

`search_threads` を以下のクエリで実行（pageSize: 50）:

```
in:inbox newer_than:4d -category:promotions -category:social -category:updates -category:forums -from:noreply -from:no-reply -from:donotreply -from:notification -from:mailer-daemon -from:bounces (日程 OR 候補日 OR ご都合 OR 日程調整 OR 現調 OR 現地調査 OR 訪問 OR 打合せ OR お打ち合わせ OR 立会 OR 立ち会い OR 何時 OR 都合のよ)
```

ヒット 0 件でも即終了せず、ステップ6のサマリー報告へ進む。

## ステップ2: スレッド詳細取得と対象判定

各スレッドに `get_thread`（messageFormat: FULL_CONTENT）。並列実行可。**1つでも該当したら除外**:

1. **返信済み**: スレッド最新メッセージの labelIds に `SENT` が含まれる
2. **CC のみ**: 最新の受信メッセージで小山さんが `toRecipients` に含まれず `ccRecipients` のみ → 除外
3. **自動送信**: 送信者が `noreply` / `no-reply` / `notification` / `mailer-daemon` / `bounces` / `info@` / `newsletter` 等
4. **日程要素なし**: 本文に日程調整の意図（候補日提示・可否確認・日時の問い合わせ・調整依頼）が無い → 除外

残ったものが「日程調整が必要な未対応メール」=自動対応対象。

## ステップ3: 自分の既知予定の把握

返信前に、`notion-search` と Gmail から小山さんの確定/予定済みの動きを収集する:

1. `notion-search`: 「シネマPJ」「振り返り」「予定」「スケジュール」「Daily Dashboard」等で検索し、ヒットしたページを `notion-fetch` で読み、今後の現調・訪問・打合せ・夜間作業の確定分を把握
2. Gmail `search_threads`: `in:sent newer_than:14d` および同一相手・物件・案件名で再検索し、既に約束済みの日時を把握
3. 同一スレッド内の過去メッセージをすべて読み、既出の候補・条件・経緯を把握

把握した予定とバッティングしうる時間帯を「埋まっている可能性が高い」と判断する。判断材料が無い時間帯は「空いている可能性」とし、断定しない。

## ステップ4: 返信案の生成

相手メールのパターンに応じて作り分ける:

- **相手が候補日を提示してきた場合**: 自分の既知予定と突合し、可否を回答。OK の候補が複数あれば第1希望を明示。すべて不可なら代替候補を2〜3案提示
- **相手が当方の都合/候補を求めている場合**: 直近で空いている可能性が高い候補を**2〜3案**提示（例: 「◯月◯日 午前」「◯月◯日 15時以降」）。あわせて確定は追って連絡する旨を添える
- **日時が曖昧（"近いうちに"等）の場合**: 具体候補を2案提示して相手の選択を促す

判断材料が不足する要素は推測で埋めず、「追って正式にご連絡いたします」等でカバーし、空欄やプレースホルダを残さない。書き出しは「いつもお世話になっております。」、結びは「何卒よろしくお願いいたします。」。

## ステップ5: 下書き保存（全員に返信 / Reply All・OK不要）

各対象について `create_draft` を呼ぶ。各スレッドの**最新の受信メッセージ**から宛先を組み立てる:

1. `to`: 最新受信メッセージの送信者（`sender`）
2. `cc`: 最新受信メッセージの `toRecipients` + `ccRecipients` を結合し、自分のアドレス・`to` との重複・大文字小文字差を除外
3. `subject`: 元件名に `Re: ` が無ければ付与
4. `body`: ステップ4の返信案
5. `replyToMessageId`: 返信対象の最新受信メッセージID

社内メンバーが CC にいてもそのまま残す。並列実行可。

## ステップ6: サマリー報告（表示して終了。確認待ちしない）

**1件以上保存した場合**:

```
✅ 日程調整チェック完了。下書き N件を作成しました。

[1] <件名>
    To: <addr> / Cc: <addr...>
    提示した候補: <候補日> ／ ※予定突合の情報源: <Notion/過去メール等>
[2] ...

Gmail の下書きを確認のうえ送信してください。仮押さえの確定は別途お願いします。
```

**0件だった場合**:

```
✅ 日程調整チェック完了。対応が必要な日程調整メールはありませんでした。
（参考）検索ヒット N件: 返信済み a件 / CCのみ・対象外 b件 / 日程要素なし c件
```

サマリーを表示したら**そのまま終了する**。
