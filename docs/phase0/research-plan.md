# Phase 0 リサーチ計画

- **ステータス**：実行済み（2026-07-16 実行・2026-07-18 統合完了。結果は [research-findings.md](research-findings.md)、成果物は [candidates.md](candidates.md)）
- **目的**：「誰がカネを払うか」から逆算し、テーマ候補3案の比較表＋推奨1案を作る
- **調査手段**：ウェブ検索・YouTube（閲覧のみ。投稿・登録・課金等の外部操作は一切しない）

## 計画（10行版）

1. **海外実例**：Indie Hackers 等で収益を公開している個人マイクロSaaSの実例を収集（数字の裏が取れるもの優先、誇大な情報商材系は除外）
2. **国内実例**：note・Zenn・X・YouTube の個人開発収益化事例を収集（同基準）
3. **型の照合**：実例群から 型①「乱れた入力→整った提出物」／型②「症状→一次切り分け」に構造が近い成功例を抽出し、価格帯・チャネル・自動化度を整理
4. **痛みの探索**：士業・教室運営・修理業・農業・物流・飲食（＋有望なら他業種）で、書類作成・一次対応の痛みの生の声を検索/YouTube/コミュニティから収集（設備業界は除外）
5. **競合・価格**：有望な痛み上位5件について既存サービス・価格帯・弱点・すき間を調査
6. **チャネル**：各顧客層の情報接点（検索/YouTube/紹介/業界団体）と「匿名運用で届くか」を確認
7. **統合**：制約フィルタ（利益相反なし・匿名可・固定費3,000円/月以内・週2〜5h運用）を通し、候補3案の比較表＋推奨1案を作成

## 各ステップの詳細

### 1〜2. 実例収集

- **ソース候補**：Indie Hackers（products / interviews）、MicroConf、個人開発者の X・note・Zenn、YouTube の個人開発・AI活用チャンネル。Starter Story 等の紹介メディアは数字を割り引いて扱う
- **検索例**：`micro saas solo founder MRR 2025` / `indie hacker revenue 2025` / `個人開発 収益 事例 2025` / `マイクロSaaS 個人 月商` など
- **採用基準**：本人発信で数字の根拠（スクリーンショット・決済プラットフォーム連動・継続的な報告）が確認できる／継続期間が分かる。情報商材への誘導が主目的の発信は除外

### 3. 型の照合

- 型①に近い例：フォーム入力→請求書/契約書/提案書生成、音声/チャット→議事録/報告書、写真→点検レポート など
- 型②に近い例：症状チェッカー、診断フロー、FAQ自動応答、一次見積シミュレーター など

### 4. 痛みの探索（型が刺さる兆候）

- **型①が刺さる兆候**：手書き・LINE・電話・口頭で受けた情報を、決まった書式（見積書・報告書・行政提出書類・保護者向け文書等）に清書する作業が頻発している業種
- **型②が刺さる兆候**：似た問い合わせ・症状相談が繰り返し来て、一次回答・切り分けに時間を取られている業種
- **探索対象**：士業（行政書士・社労士・税理士等）、教室運営（塾・音楽・スポーツ）、修理業（自動車・自転車・スマホ・家電）、農業、物流（軽貨物・小規模運送）、飲食。有望な兆候があれば近隣業種（清掃、便利屋、リフォーム外の職人など）にも広げる
- **注意**：商業施設・シネコン向け空調/省エネ、および設備業界向け全般は利益相反のため対象外

### 5〜6. 競合・チャネル

- 競合：既存SaaS・Excelテンプレ販売・代行サービスまで含めて「その痛みに今カネがどう流れているか」を見る
- チャネル：その顧客層が検索するか／YouTubeを見るか／紹介・組合文化か。匿名運用（顔出しなし）で届くかを必ず判定

### 7. 成果物：比較表の列

払う人／痛みの深さ／競合／価格案／集客チャネル／自動化度／立ち上げ工数／リスク（＋制約フィルタ判定：利益相反・匿名・固定費・週2〜5h）

## 除外基準（最初から候補にしない）

- 本業（商業施設・シネコン向け空調/省エネ）と競合するもの、設備業界向け全般
- 顔出し・実名が事実上必須のモデル（属人コンサル型など）
- 規約違反となるスクレイピング・自動投稿を前提とするもの
- 収益の裏が取れない事例だけを根拠にした構想
- 月額固定費3,000円を超えるインフラが前提のもの
